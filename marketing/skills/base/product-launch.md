# Product Launch

Every launch (from a blog post to a market entry) deserves a plan that is sized correctly for
its risk and impact. This skill helps you right-size the launch, build the GTM plan, manage risks,
and capture the lessons for next time.

---

## Step 1: Size the Launch (Tier Scoring)

Score the launch against these criteria to determine the right tier:

```markdown
### Launch Scope Assessment: [Launch Name]

**What are we launching?** [product / feature / region / capacity / pricing change]
**Launch date target**: [date]

Score each criterion 1 to 3 (1=low, 2=medium, 3=high):

| Criterion | Score | Notes |
|-----------|-------|-------|
| ARR / pipeline impact potential | | |
| New customer segments reached | | |
| Competitive urgency | | |
| Engineering / product effort involved | | |
| Regional / regulatory complexity | | |
| Exec visibility required | | |
| Partner / customer commitments | | |

**Total Score**: [X]/21
```

### Tier Thresholds

| Tier | Score Range | What It Means |
|------|-------------|---------------|
| **Tier 1** | 15 to 21 | Major launch: full war room, exec involvement, all channels, coordinated PR |
| **Tier 2** | 8 to 14 | Standard launch: dedicated workstreams, milestone reviews, key channels |
| **Tier 3** | 1 to 7 | Low-key launch: blog post + email, minimal coordination, self-service assets |

## Step 3: Risk Register

For every launch above Tier 3, complete a risk register before go/no-go:

```markdown
## [Launch Name]: Risk Register

| Risk | Category | Likelihood (H/M/L) | Impact (H/M/L) | Owner | Mitigation | Fallback | Status |
|------|----------|--------------------|----------------|-------|------------|----------|--------|
| | | | | | | | |
```

### Risk Categories to Check

| Category | Common Risks |
|----------|-------------|
| **Product & Reliability** | Feature readiness, bugs, infrastructure load, rollback path |
| **Go-to-Market** | Messaging accuracy, asset approvals, channel readiness, partner alignment |
| **Compliance & Legal** | Policy review, privacy terms, licensing, regional constraints |
| **Support & Success** | Staffing levels, escalation handoffs, enablement coverage |
| **External Factors** | Competitor moves, macro events, press sentiment |

## Step 4: Go/No-Go Checklist

Run this 48 to 72 hours before launch:

```markdown
## Go/No-Go: [Launch Name]: [Date]

### Product Readiness
- [ ] Feature complete and tested
- [ ] Rollback plan documented and tested
- [ ] Infrastructure load tested (Tier 1 only)
- [ ] On-call rota confirmed for launch week

### Marketing Readiness
- [ ] All assets approved (copy, design, legal)
- [ ] Email campaigns scheduled and tested
- [ ] Blog post / landing page live in staging
- [ ] Social posts scheduled
- [ ] Press embargo set (if applicable)

### Sales & CS Readiness
- [ ] Battlecards updated
- [ ] Sales team briefed
- [ ] CS / support team briefed
- [ ] FAQ document published internally

### Risk Review
- [ ] All High risks have mitigations and owners
- [ ] Escalation path documented
- [ ] War room schedule set (Tier 1 only)

**DECISION**: ✅ Go / ❌ No-Go / ⚠️ Conditional Go
**Conditions** (if applicable): [what needs to be resolved before launch]
```

---

## Tips

- Reassess tier mid-cycle if scope or market conditions shift significantly
- Pre-populate risk banks per tier to accelerate planning for future launches
- Tie risk mitigations to instrumentation/alerts so issues surface automatically
- Share daily summaries with execs during Tier 1 launches, no surprises
- Keep a historical log of tier decisions for benchmarking and budgeting
