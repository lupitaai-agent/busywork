# Busywork

Free, private tools for small businesses and freelancers, with the Marketing Studio for owners who
do their own marketing.

**Olaf**, the paid AI marketing expert, is not in this repository. It lives in a private repository
(`busywork-olaf`) and ships only in the paid download. This repository holds its website demo
(`olaf-demo/`) and the fingerprints that keep its paid text off the website. Free pages detect
whether Olaf is installed (`apps/olaf/olaf-installed.js`) and otherwise link to the Olaf page.

Everything runs in the browser. There is no server and no account: data lives in a folder the
owner picks. The free tools have no AI; Olaf (paid, private repository) uses the owner's own Claude
API key, sent only to Anthropic. The website's copy of the tools is a demo with a pretend business
(`website/assets/demo.js`): nothing is kept after the tab closes.

| Folder | What it is |
|---|---|
| `app/` | The free tools, the Marketing Studio included. Plain HTML, CSS and JavaScript, no build step; they work from `file://`. |
| `marketing/` | The marketing foundation (proven brand growth science) and the Marketing Studio's playbooks. |
| `olaf-demo/` | The website demo of Olaf, made by the private Olaf build. Screens and the example business only: no skill instructions, no AI. Don't edit. |
| `olaf-fingerprints.json` | One-way hashes of Olaf's paid text, made by the private Olaf build. `build.py` refuses to publish anything that matches. |
| `website/` | The public site. Some of it is generated (see below). |
| `build.py` | Builds everything generated: skill bundles, the online copy of the tools, the download zip, product pages, sitemap. |
| `check.py` | Every check in one command: scripts parse, logic tests, build tests, a real build with the leak check. |
| `tests/` | Tests that run with Node and Python alone, no packages. |
| `ARCHITECTURE.md` | How it is built and why, the seams for desktop, store and cloud versions, and how far away each is. |
| `DATA.md` | The data format of a business folder, data versions and backups. Every collection is listed. |

## Build and preview

```bash
python3 build.py
```

Then open `website/index.html`, or serve the folder (`python3 -m http.server -d website`) so the
tools can use a folder on disk.

Generated files are not committed (see `.gitignore`); `build.py` makes them and the GitHub
workflow runs it on every push.

Before committing, run every check (Node 22+ and Python 3.9+, nothing to install):

```bash
python3 check.py
```

GitHub runs the same command before every deploy, and on every pull request.

## Publish on GitHub Pages

1. Create the repository on GitHub and push this folder to `main`.
2. In the repository: **Settings → Pages → Source: GitHub Actions**.
3. Every push to `main` runs `.github/workflows/pages.yml`: it runs `check.py`, builds the site and publishes
   `website/`. The real address is passed to the build as `SITE_URL`, so canonical links and the
   sitemap are right. A custom domain set under Settings → Pages is picked up the same way.

## Going live with your own domain

1. **GitHub:** create the public repository `busywork`, push this folder to `main`, then
   Settings → Pages → Source: **GitHub Actions**. The site is up at `https://<you>.github.io/busywork/`
   after the first run.
2. **Domain:** Settings → Pages → Custom domain → type your domain (for example `busywork.nl`) and save.
   At your domain registrar, add DNS records:
   - for `www`: a `CNAME` record pointing to `<you>.github.io`
   - for the bare domain: four `A` records to `185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
     `185.199.111.153`

   When GitHub shows the domain as verified, tick **Enforce HTTPS**. DNS can take a few hours. The
   workflow passes the domain to the build, so links, the sitemap and the "Get Olaf" links use it.
3. **Waitlist:** create a free form at formspree.io, copy its address (`https://formspree.io/f/…`), and
   add it under Settings → Secrets and variables → Actions → Variables as `WAITLIST_ENDPOINT`. Run the
   workflow again (Actions → Publish website → Run workflow). Sign-ups arrive by email and in Formspree.
   Using another form service? Set `WAITLIST_PROVIDER` and update the waitlist paragraph in
   `website/privacy.html`.
4. **Before you share the link:** fill in the company details in `website/privacy.html` and
   `website/terms.html`.

## Rules worth keeping

- Never hand-edit generated files: `website/app/`, `website/tools/`, `website/downloads/`,
  `website/sitemap.xml`, `website/robots.txt`, `app/apps/*/library.js`, and the parts of
  `olaf/skills/` marked "Generated by". Edit the source and rebuild.
- Ads (AdSense) appear on the website only, never inside the tools or their output.
- Skills are vetted text: no hidden characters, no instructions that fetch or update themselves.
  `build.py` refuses to bundle Olaf's library if it finds names that must not ship.
- Third-party credits for adapted skills are in `marketing/licenses/`.
